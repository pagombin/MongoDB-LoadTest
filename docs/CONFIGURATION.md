# Configuration

Ballast reads one YAML file, `config/ballast.yaml` in the install directory. Start from the example:

```
cp config/ballast.yaml.example config/ballast.yaml
```

The file is optional; without it every key has its default.

## Precedence

From highest to lowest:

1. Command-line flags: `--set section.key=value` (repeatable) and the shortcut `--listen HOST:PORT`.
2. Environment variables: `BALLAST_<SECTION>_<KEY>`, for example `BALLAST_SERVER_LISTEN=0.0.0.0:8443`.
3. The configuration file.
4. Defaults.

`bin/ballast config print` shows the effective value of every key and where it came from (`flag`, `env`, `file` or `default`). The System page shows the same table. Secrets are shown as `****`.

Other environment variables:

| Variable | Meaning |
|---|---|
| `BALLAST_CONFIG` | Path of the configuration file, instead of `config/ballast.yaml`. Relative paths resolve against the install directory. |
| `BALLAST_HOME` | Install directory. `bin/ballast` sets it; you do not need to. |

Any other variable starting with `BALLAST_` that does not name a known key stops startup with an error naming it. Values from environment variables and `--set` are parsed as YAML scalars, so `true`, `8443` and `[a, b]` become a boolean, a number and a list.

## Validation

Unknown keys and invalid values stop startup with a message that names the key:

```
$ bin/ballast config validate
error: invalid configuration (/home/me/ballast-1.0.0/config/ballast.yaml):
  server.listn: unknown key
```

`bin/ballast config validate [FILE]` checks a file without starting anything and exits 0 when it is valid, 2 when it is not. It also prints a warning for secret files that other users can read.

## Paths

Relative paths in the file, environment and flags resolve against the install directory (the directory that holds `bin/`), never the current working directory. Absolute paths are used as given.

## Secrets

The access token can be given inline (`server.access_token`), from an environment variable (`server.access_token_env` names the variable), or from a file (`server.access_token_file`). Set only one. Target passwords in the `targets` list work the same way (`password`, `password_env`, `password_file`). A secret file should be readable only by you:

```
chmod 600 config/token
```

Ballast warns at startup, in `bin/ballast config validate`, and on the System page when a secret file is readable by group or others.

## Keys

### `server`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `server.listen` | `127.0.0.1:8443` | `BALLAST_SERVER_LISTEN` | Address and port to listen on. Ports below 1024 are refused, because they need root. Use `0.0.0.0:8443` to listen on all interfaces. |
| `server.public_url` | `""` | `BALLAST_SERVER_PUBLIC_URL` | The URL users open, if it differs from the listen address (for example behind a reverse proxy). Used for redirects and the same-origin check. |
| `server.trust_proxy_headers` | `false` | `BALLAST_SERVER_TRUST_PROXY_HEADERS` | Trust `X-Forwarded-Proto` and `X-Forwarded-Host` from a reverse proxy that terminates TLS. Turn on only when Ballast is reachable solely through that proxy. |
| `server.access_token` | `""` | `BALLAST_SERVER_ACCESS_TOKEN` | Inline access token. When any token is set, every request needs it. |
| `server.access_token_env` | `""` | `BALLAST_SERVER_ACCESS_TOKEN_ENV` | Name of an environment variable holding the token. |
| `server.access_token_file` | `""` | `BALLAST_SERVER_ACCESS_TOKEN_FILE` | File holding the token (first line). |
| `server.max_body_kb` | `1024` | `BALLAST_SERVER_MAX_BODY_KB` | Largest request body accepted, in KB. |
| `server.shutdown_timeout_seconds` | `30` | `BALLAST_SERVER_SHUTDOWN_TIMEOUT_SECONDS` | How long a stop waits for an active run to drain and save. |

### `tls`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `tls.mode` | `self-signed` | `BALLAST_TLS_MODE` | `off`, `files` (your certificate and key) or `self-signed` (generated by Ballast). |
| `tls.cert_file` | `certs/server.crt` | `BALLAST_TLS_CERT_FILE` | Certificate (PEM, full chain) in `files` mode; where the generated one is written in `self-signed` mode. |
| `tls.key_file` | `certs/server.key` | `BALLAST_TLS_KEY_FILE` | Private key (PEM). Written with mode 0600 in `self-signed` mode. |
| `tls.self_signed_hosts` | `["localhost", "127.0.0.1"]` | `BALLAST_TLS_SELF_SIGNED_HOSTS` | Host names and IP addresses placed in the generated certificate. The listen address is added when it is a specific address; when it is `0.0.0.0` or `::`, the host's name and the addresses it can see are added. Changing this list regenerates the certificate at the next start. |
| `tls.min_version` | `"1.2"` | `BALLAST_TLS_MIN_VERSION` | `1.2` or `1.3`. |
| `tls.redirect_http_listen` | `""` | `BALLAST_TLS_REDIRECT_HTTP_LISTEN` | Optional plain HTTP listener, for example `0.0.0.0:8080`, that only redirects to HTTPS. |

HSTS is sent only in `files` mode, so browsers never pin a self-signed certificate.

### `paths`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `paths.data_dir` | `data` | `BALLAST_PATHS_DATA_DIR` | Saved targets, profiles, runs and per-second data (`ballast.db`, mode 0600). |
| `paths.log_dir` | `logs` | `BALLAST_PATHS_LOG_DIR` | `ballast.log`, `supervisor.log`, `console.log`. |
| `paths.run_dir` | `run` | `BALLAST_PATHS_RUN_DIR` | PID files and the readiness file. |
| `paths.min_free_disk_mb` | `200` | `BALLAST_PATHS_MIN_FREE_DISK_MB` | Startup fails if the data disk has less free space than this. |

### `logging`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `logging.level` | `info` | `BALLAST_LOGGING_LEVEL` | `debug`, `info`, `warning` or `error`. |
| `logging.format` | `json` | `BALLAST_LOGGING_FORMAT` | `json` (one object per line) or `text`. |
| `logging.max_size_mb` | `100` | `BALLAST_LOGGING_MAX_SIZE_MB` | Rotate a log file when it reaches this size. |
| `logging.max_files` | `10` | `BALLAST_LOGGING_MAX_FILES` | Rotated files to keep per log. |

### `retention`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `retention.runs_max_age_days` | `0` | `BALLAST_RETENTION_RUNS_MAX_AGE_DAYS` | Delete finished runs older than this. 0 keeps them forever. |
| `retention.runs_max_count` | `0` | `BALLAST_RETENTION_RUNS_MAX_COUNT` | Keep at most this many runs, newest first. 0 means no limit. |

Retention runs at startup and then hourly. It never deletes an active run.

### `branding`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `branding.product_name` | `Ballast` | `BALLAST_BRANDING_PRODUCT_NAME` | Name shown in the UI, page titles and reports. |
| `branding.logo_file` | `""` | `BALLAST_BRANDING_LOGO_FILE` | SVG, PNG, JPEG or WebP shown in the navigation rail instead of the Ballast wordmark. Height 22 px. |
| `branding.accent_color` | `""` | `BALLAST_BRANDING_ACCENT_COLOR` | Hex color such as `#7A3E9D` for primary buttons, focus rings and markers. Choose one with at least 4.5:1 contrast against white. |

### `supervisor`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `supervisor.restart_backoff_initial_seconds` | `1` | `BALLAST_SUPERVISOR_RESTART_BACKOFF_INITIAL_SECONDS` | Wait before the first restart after a crash. Doubles each time. |
| `supervisor.restart_backoff_max_seconds` | `60` | `BALLAST_SUPERVISOR_RESTART_BACKOFF_MAX_SECONDS` | Longest wait between restarts. |
| `supervisor.max_restarts` | `5` | `BALLAST_SUPERVISOR_MAX_RESTARTS` | Give up after more than this many crashes within the window. |
| `supervisor.restart_window_seconds` | `120` | `BALLAST_SUPERVISOR_RESTART_WINDOW_SECONDS` | The window for counting crashes. A server that runs longer than this resets the backoff. |
| `supervisor.stop_timeout_seconds` | `45` | `BALLAST_SUPERVISOR_STOP_TIMEOUT_SECONDS` | How long a graceful stop waits before killing the server. |

### `features`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `features.legacy_dashboard` | `false` | `BALLAST_FEATURES_LEGACY_DASHBOARD` | Allow `bin/ballast legacy run -c FILE`, the original Dash dashboard. See `docs/LEGACY.md`. |
| `features.prometheus_metrics` | `true` | `BALLAST_FEATURES_PROMETHEUS_METRICS` | Serve `GET /metrics` (behind the access gate when one is set). See `docs/OPERATIONS.md`. |

### `notifications`

| Key | Default | Environment variable | Meaning |
|---|---|---|---|
| `notifications.webhook_url` | `""` | `BALLAST_NOTIFICATIONS_WEBHOOK_URL` | URL to POST Slack-compatible JSON to. Empty turns notifications off. |
| `notifications.events` | `["run_finished", "guardrail"]` | `BALLAST_NOTIFICATIONS_EVENTS` | Any of `run_started`, `run_finished`, `guardrail`, `disruption`. |
| `notifications.timeout_seconds` | `5` | `BALLAST_NOTIFICATIONS_TIMEOUT_SECONDS` | How long one delivery may take. |

The configuration file is read with PyYAML when it is installed. Without it a built-in reader handles mappings, lists, flow lists such as `["a", "b"]`, quoted and plain scalars, comments and block text. It refuses anchors, aliases, tags and multiple documents with a message saying so.

### `targets`

An optional list of targets created at startup, for scripted installs. Targets added in the UI do not need this. Each entry takes `name`, `uri`, one of `password` / `password_env` / `password_file`, and optionally `tls` (`auto`, `on`, `off`), `tls_ca_file`, `tls_certificate_key_file`, `tls_allow_invalid_hostnames`. The password replaces any password in `uri`.

```yaml
targets:
  - name: prod
    uri: mongodb+srv://bench@cluster0.example.net/?authSource=admin
    password_file: config/prod-password
```

## Example: all interfaces, real certificate, access token

```yaml
server:
  listen: 0.0.0.0:8443
  access_token_file: config/token
tls:
  mode: files
  cert_file: /home/me/certs/fullchain.pem
  key_file: /home/me/certs/privkey.pem
  redirect_http_listen: 0.0.0.0:8080
```

## Example: behind a reverse proxy that terminates TLS

```yaml
server:
  listen: 127.0.0.1:8443
  public_url: https://ballast.example.com
  trust_proxy_headers: true
tls:
  mode: "off"
```
